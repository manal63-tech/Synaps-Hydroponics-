# Synaps Hydro — rebuilt backend + new dashboard

**Quick start:**
```bash
pip install -r requirements.txt
python app.py
```
Open **http://localhost:5000** — the new dashboard is served directly at `/`.
The ESP32 sends readings to `/api/sensor-data`; the dashboard displays
available sensor values and leaves disconnected sensors empty.
```bash
curl -X POST http://localhost:5000/api/sensor-data -H "Content-Type: application/json" \
  -d '{"temperature":24,"humidity":65}'
```

## What changed since your old code

The current application uses deterministic sensor validation and
agronomic safety rules only. Machine-learning inference has been removed
until a replacement model is developed and explicitly integrated.

In short:
- Sensor values are checked against explicit physical bounds and
  independent agronomic ranges; absent sensor readings remain empty.
- The Isolation Forest artifact and loader have been removed. A future
  model can be developed and integrated separately.
- `hydromon/templates/index.html` is now the new Synaps Hydro dashboard
  (light/dark mode, EN/FR/AR with RTL), wired to your real endpoints
  (`/api/latest`, `/api/history`, `/api/led`) — no mock sensor data.
- Alert samples are grouped into incidents, live readings are marked stale
  after missed device updates, and sensor health distinguishes missing data
  from hardware faults.
- History periods now filter stored UTC timestamps, custom date ranges are
  available, and charts show real time spacing and localized temperature units.
- Language, theme, display units, refresh interval, and browser notification
  preferences are saved locally. Browser notifications require permission.

## Known limitations (be aware, not blocking)

- Alert text generated by `decision.py` is French-only for now — the
  dashboard's language switcher translates the UI chrome, not these
  backend-generated messages.
- Browser notifications are delivered only while the dashboard is in the
  background and the browser has granted notification permission.
- Current safe ranges are rule-based starting values and should be
  reviewed against the project's agronomic references.
